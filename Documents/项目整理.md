## 0. 一页结论

1. **当前项目实质是旧 GDD 的“阶段一/刻印系统 MVP”加上基础战斗、敌人与信息素原型。** 三槽两位格、本位/变位事件通信、蓄力、8 枚 MVP 刻印、伤害/抗性/状态、敌人基础 AI、库存 UI 已具备；完整可玩的 Rogue-like 循环尚未形成。

2. **新 GDD 把目标从“刻印系统 MVP”升级为“双段波次 + 信息素喂养 + 词条成长 + 残响轮回”的完整 Demo。** 现有代码有三块需要重构而非小补：**敌人/波次模型、信息素/抗性模型、刻印成长闭环**。

3. **开发路线应以“先形成单层可玩闭环，再扩展成长与内容”为原则。** 先修复基础问题并跑通“小怪波 → Boss 波 → 顿悟 → 坠落”的单层纵向切片，再补词条、融合、残响、瞬切与 5~8 层内容，避免在底层规则未稳定时堆内容。

4. **近期最先要做的不是新功能，而是基础一致性：** 库存 8 格与重复获取规则、空槽默认能力、事件上下文可修改、敌人计数 bug、AI 标签命名统一、文档与代码对齐。

### 1.4 当前可演示流程（静态推断）

1. `MainMap` 使用 `BP_C_GameMode`；玩家蓝图引用 8 枚刻印，通过 `AddGlyph` 发放到库存（用于演示）。
2. `Tab` 打开库存，把刻印拖到普攻/技能/位移槽的本位或变位位置；关闭后左键 / `E` / 右键分别触发三槽。
3. 功能槽 Ability 是薄壳，激活后交给 `UGlyphInventoryComponent::ActivateSlotGlyph`；有蓄力配置时先走蓄力流程，完成后调用刻印本位逻辑。
4. 敌人与玩家共用 `UC_GlyphInventoryComponent`，由 `GiveGlyph(Level, GlyphPool)` 从权重池抽取 N 枚刻印并依次填入 6 个槽；行为树按冷却和槽位标签移动/释放。
5. 敌人死亡时调用 `GameMode::SpawnPheromone` 生成死亡点信息素，并通知 BP 波次；BP GameMode 的 `SpawnEnemysByWave` 继续生成敌人。
6. **当前没有：** Boss 波、层数/坠落、玩家死亡处理、双视角、词条/顿悟/融合/图鉴/存档/瞬切；`AC_Pheromone` 也不参与新 GDD 的抽取权重与抗性计算。

## 2. 新旧 GDD 差异

### 2.1 核心差异对照

| 主题 | 旧 GDD v1.0 | 新 GDD v2.0 | 对现有实现的影响 |
|---|---|---|---|
| 核心循环 | 探索层数 → 击杀敌人领悟刻印或积攒灵感 → 库满舍弃 → 灵感满顿悟 → 死亡下一轮回 → 每五层异象并重置抗性 | 初始池 → 小怪波（割草/信息素/爆刻印/概率顿悟）→ Boss 波（吸收信息素生成刻印怪）→ 击败必顿悟 → 坠落更深层 → 每五层异象 → 死亡下一轮回 | 需要新增波次/层流程；现有 BP 波次只是雏形 |

### 2.2 三大重构点

**（1）敌人与波次模型：从“一个通用三槽敌人”变成“小怪 + Boss 刻印怪”双轨。**  
现有 `AC_EnemyCharacter`、`GiveGlyph`、行为树、BP 波次都是以“敌人就是缩小版玩家”为前提。新 GDD 要求小怪行为/外貌固定且不参与标签决策，只有 Boss 波刻印怪复用三槽、体型/变位/抗性可读。这不是改参数，而是需要拆分敌人类型、生成入口和 AI 适用范围。

**（2）信息素与抗性：从“死亡点标签”变成“层内元素账户 + Boss 吸收”。**  
旧模型靠死亡点 Actor 记录标签、三波生命周期、点内抗性叠加；新模型要求在本层内按元素累积、Boss 波吸收归零、用累积结果决定刻印怪抽取权重和抗性。现有 `AC_Pheromone` + `GameState` 只能支撑“生成位置/最后一次击杀刻印类”，不能支撑新链路。

**（3）成长闭环：从“重复升级 + 灵感顿悟”变成“二选一 + 词条 + 概率顿悟 + 残响/瞬切”。**  
这是新增内容最多的一块：刻印基类要承载等级/词条/融合状态；库存要处理容量、唯一性、重复二选一、舍弃/替换/残响；顿悟要能融合两枚刻印、升级或跳过；残响要跨局存档；槽位要能预存和瞬切。现有代码在这些方面基本为空壳或 TODO。

## 3. 已开发功能明细

### 3.1 GAS、角色与属性

- 玩家 `AC_PlayerState` 持有 `UAbilitySystemComponent` 和 `UC_AttributeSet`；`AC_PlayerCharacter` 实现 `IAbilitySystemInterface` 并把 ASC 初始化到 PlayerState。
- 敌人 `AC_EnemyCharacter` 自带 ASC 和 AttributeSet；`AC_BaseCharacter` 提供 `StartupAbilities` 统一发放能力。
- `UC_AttributeSet` 包含生命、最大生命、`IncomingDamage` 元属性、火/水/风/土四抗性；`PostGameplayEffectExecute` 统一处理伤害、抗性、格挡与减伤，并在生命归零时把伤害来源刻印类交给 `HandleDeath`。
- 输入：Enhanced Input；Walk/Look/Attack/Skill/Move/Menu；菜单打开时禁止 Look 与三槽 Ability，允许移动；三槽按键松开时调用 `EndRunningCharge`。
- 相机：只有第三人称 SpringArm + FollowCamera。

### 3.2 刻印框架

- `UC_GlyphBase`（UObject）：`GlyphName`、`GlyphAttribute`、`GlyphType`、三套 `FGlyphConfigurationContext`（Attack/Skill/Move）、`RunningConfiguration`、`OwningAbility`。
- 三槽入口：`AttackBase` / `SkillBase` / `MoveBase`（BlueprintImplementableEvent），由 `ActivateGlyph` 按 `GlyphType` 分发；`ApplyCooldown` 为蓝图事件。
- 事件：`EBaseEventType`（OnCast/OnSpawn/OnTravel/OnHit/OnFinish）、`FBaseEventReceived` 多播委托、`BaseEvent` 广播、`BaseEventReceived` 蓝图响应。
- 变位接入：
  - `PreProcessContext(BaseGlyphType, Context)`：返回修改后的配置，属于“数据修改”；
  - `PreActivate()`：激活前蓝图钩子；
  - `BaseEventReceived(EventType, Context)`：事件挂载增量逻辑。
- 当前 8 枚刻印分别使用了上述三条路径；说明“变位修饰本位”的基本链路已跑通，但事件上下文目前是 `const`，变位无法在运行时修改事件数据（详见 4.2）。
- 工具函数：`CreateWaitGameplayEventTask`、`CreatePlayMontageAndWaitTask`、`SpawnActor`、球/盒/线碰撞检测、`ApplyDamageToTarget`、`ApplyEffectToTarget`、`TryEndAbility`。
- 生成物 `AC_GlyphSpawnActor`：携带伤害/元素/速度/穿透标记；`Orbit` 模式在 Tick 中围绕 Owner 旋转；自带 `UC_TravelEventComponent` 可广播 `OnTravel`。
- `UC_TravelEventComponent`：按时间间隔或移动距离广播 `OnTravel`，挂载于角色或生成物。

### 3.3 库容与槽位

- `UC_GlyphInventoryComponent` 持有 `GlyphInventory` 数组和三组 2 元素槽位数组（Attack/Skill/Move）。
- 提供 `AddGlyph`、`RemoveGlyph`、`SetGlyphType`（移动/交换槽位）、`RemoveAllGlyph`、`NameToGlyph`、`GetSlotContent`。
- 槽位变化通过 `OnGlyphInventoryChange` 和 `OnGlyphTypeChange` 广播，UI 组件据此刷新。
- 执行入口 `ActivateSlotGlyph(SlotType, Ability)`：取本位配置 → 变位 `PreProcessContext`/`PreActivate` → 本位 `PreActivate` → 无蓄力则直接 `ActivateGlyph`，有蓄力则进入蓄力流程。
- 变位事件绑定：`BindGlyph`/`UnbindGlyph` 在槽位变化时把本位 `OnBaseEvent` 绑定到同槽变位的 `BaseEventReceived`。
- **注意：** 容量 8、唯一性、重复获取尚未实现，`AddGlyph` 中有明确的 MVP 注释（`C_GlyphInventoryComponent.cpp:25`）。

### 3.4 蓄力系统

- `FGlyphConfigurationContext` 内含 `TArray<FGlyphChargeContext>`，每段包含蓄力时间、蓄力蒙太奇、伤害/碰撞/生成物伤害/尺寸/速度/持续时间/位移倍率。
- `ActivateSlotGlyph` 在进入蓄力时记录 `RunningGlyph`、`ChargeStartTime`、`ChargeIndex`，按 `MontageRate` 调整每段时长。
- `TickComponent` 以绝对时间差推进 `ChargeIndex`，每段达到时播放对应蒙太奇；完成或中断时 `SettleCharge` 按实际蓄力时长应用倍率，再调用 `ActivateGlyph`。
- 蓄力蒙太奇直接通过 `AnimInstance->Montage_Play` 播放，绕过 AbilityTask 的异步激活时序问题（对应新 GDD §9.3.2 的修复记录）。
- 蒙太奇中的 `UAnimNotify_SendGameplayEvent` 配合 `CreateWaitGameplayEventTask` 在刻印蓝图内监听蓄力过程事件。

### 3.5 战斗内容与状态效果

- 8 枚刻印各自的攻击/技能/位移蒙太奇、投射物/范围生成物、变位效果均已存在。
- GE 资源包括：伤害、火/水/风/土 DOT、治疗、格挡、减伤、净化、隐身、遁地、减速、冷却（Attack/Skill/Move）。
- 伤害入口 `ApplyDamageToTarget`：设置 `SetByCaller` 伤害值、把元素枚举转为 `CTags.Datas.Elements.*` 动态标签、应用伤害 GE，并向目标发送 `CTags.Events.Hit` 事件。
- `ApplyEffectToTarget`：通过 `SetByCaller` 传递持续时间，按等级应用 GE；DOT/Buff 的元素类型由 GE 蓝图静态配置。
- 敌人血条：`UC_EnemyWidgetComponent` 按属性映射绑定 `UC_AttributeSet`，`UC_EnemyStateWidget` 提供 `BP_OnAttributeChange`。

### 3.6 敌人与 AI

- `AC_EnemyCharacter::GiveGlyph(Level, GlyphPool)`：从 `TMap<TSubclassOf<UC_GlyphBase>, float>` 权重池中**无放回**抽取 `Level` 枚刻印，然后按固定顺序填入 6 个槽位：
  `AttackBase → SkillBase → MoveBase → AttackVariant → SkillVariant → MoveVariant`。
- 敌人死亡 `HandleDeath`：清空刻印、调用 `GameMode::SpawnPheromone`、从 GameMode 敌人列表移除、执行蓝图死亡表现并销毁。
- 行为树资源：
  - 黑板 `B_Enemy`：`TargetActor`、`AttackGlyph`/`SkillGlyph`/`MoveGlyph`（Name）、`AttackInCD`/`SkillInCD`/`MoveInCD`（Bool）。
  - Task：`BTT_FindTarget`、`BTT_Move`、`BTT_TowardTarget`、`BTT_MoveToByAttackTag`、`BTT_MoveToBySkillTag`、`BTT_MoveToByMoveTag`、`BTT_Attack`、`BTT_Skill`。
  - Decorator：`BTD_CanAttack`、`BTD_CanSkill`、`BTD_CanMove`（检查冷却布尔）。
  - Service：`BTS_AbilityCooldown`（读取 `Tags.Cooldown.Attack/Skill/Move` 更新黑板）。
- 行为树的做法是：标签决定“保持距离/接近”，冷却决定是否释放；释放统一通过 `TryActivateAbilitiesByTag(CTags.Abilities.*)` 调用三个功能槽 Ability，符合“Ability 只做入口”的方向。
- 已覆盖的标签语义有限：`Melee`、`Range`、`Dash`、`Escape`、`Effect`；没有 `AOE`、`Heal`、`Summon`；没有距离/生命百分比/威胁状态黑板键。

### 3.7 信息素雏形

- `AC_Pheromone`：`Radius`、`MarkedGlyphClass`；死亡时由 GameMode 在敌人位置生成。
- `AC_GameState`：维护 `Pheromones` 数组，提供 `AddPheromone`/`RemovePheromone`/`FindPheromonesNear`。
- BP GameMode 的 `SpawnEnemysByWave` 会调用 `FindPheromonesNear`，说明旧 GDD 的“死亡点附近生成敌人”思路已有蓝图雏形。
- **与旧 GDD 也不完整：** 没有记录元素+行为标签集合、没有三波生命周期、没有点内抗性、没有 3 倍权重计算；与新 GDD 的层内累积/吸收模型差距更大。

### 3.8 UI 与输入

- `UC_UIComponent`：监听库存变化与槽位变化，转发给 `UC_GlyphInventoryWidget`；在 BeginPlay 创建库存 Widget。
- `BP_C_GlyphInventoryWidget`：库存区 + 6 个槽位；`BP_GlyphWidget` 展示刻印条目，`BP_GlyphSlot` 调用 `NameToGlyph` 和 `SetGlyphType`，`BP_GlyphDetail` 展示详情。
- `BP_GlyphWidget` 读取 `DT_Glyph`/`S_Glyph` 的图标数据；`S_Glyph` 目前只有展示相关字段（Icon 等）。
- 菜单：Tab 打开/关闭库存，GameAndUI 输入模式，显示鼠标；打开时禁止 Look 与三槽 Ability。
- 未实现：词条/等级显示、舍弃确认、重复二选一、图鉴、融合、瞬切、信息素槽、Boss 标签、双视角 HUD。

### 3.9 关卡与数据

- `MainMap` 为默认地图，默认 GameMode 为 `BP_C_GameMode`。
- `DT_Glyph` 有 8 行，RowName 对应 8 枚刻印，仅用于 UI 展示；技能逻辑参数在刻印蓝图的 `FGlyphConfigurationContext` 默认值中。
- 敌人初始刻印池、体型权重、波次参数由 BP GameMode/BP Enemy 配置，未进入 C++ 数据资产。
